ClinicOne — Booking Management

Reservations • Doctor Handshake • Rooms & Devices • Portal & Feedback

Production-ready booking for front-desk teams that keeps a clean separation between Booking (reservation) and Appointment (clinical schedule in clinic_doctor). Compatible with Odoo 19 Community Edition.

Odoo 19 CE Multi-company Mail/Activities Portal Calendar

Overview

The module centralizes patient reservations with robust overlap prevention, room/device allocation, and an optional handshake to clinic_doctor for creating or linking clinic.appointment on confirmation. It includes portal-ready links for patient access and post-care feedback, billing and stock hooks, and extensible policies/channels to fit both walk-in and online booking scenarios.

Key Features

  • Lifecycle: Draft, Confirmed, In Progress, Done, Cancelled with chatter & activities
  • Doctor/Room overlap prevention + slot-based scheduling (optional)
  • Rooms & resources (devices/tools) with capacity/compatibility flags
  • Policy & channel (cancellation window, deposits, walk-in/phone/web)
  • Portal & feedback links (secure tokens) and email templates
  • Invoice creation (optional) and inventory hooks for consumables
  • Calendar/Kanban/List/Search views with filters and smart buttons
  • Bulk confirm, reschedule, cancel via dedicated wizards

Core Models

  • booking.booking — master reservation (patient, doctor, treatment, schedule, room, state)
  • booking.line — items/services/consumables per booking
  • booking.room, booking.resource, booking.slot
  • booking.policy, booking.channel

Inherits/links: res.partner (patient), clinic.doctor, clinic.treatment, account.move, stock.picking. Appointments (clinic.appointment) live in clinic_doctor.

Holistic Integrations (24 Modules)

Seamless with: clinic_base, clinic_patient, clinic_doctor, clinic_treatment, clinic_billing, clinic_ar, clinic_ap, clinic_finance, clinic_accounting, clinic_inventory, clinic_ecommerce, clinic_membership, clinic_feedback, clinic_reports, clinic_dashboard, clinic_wallet, clinic_package, clinic_pricing, clinic_room_device, clinic_hr, clinic_portal, clinic_marketing, clinic_l10n_id, clinic_audit.

Integrations are soft-coupled via relations, activities, server actions, mail templates, and routes to keep modules independently deployable.

Installation

  1. Add this addon to your Odoo addons_path.
  2. Update Apps list, search ClinicOne: Booking Management.
  3. Install; dependencies auto-resolve.

Configuration

  • Enable sequence for booking.booking
  • Define Policies (cancellation/deposit) & Channels (Walk-in/Phone/Web)
  • Create Rooms & Resources, set capacity/compatibility
  • (Optional) Define Slots and link mail templates & server actions

Security

  • Groups: Booking Receptionist, Doctor, Booking Manager, Admin
  • Record Rules: company scope, assignment-based access, portal visibility for patient

Demo & Testing

  • Demo data: booking_demo.xml, booking_room_demo.xml, booking_resource_demo.xml, booking_policy_demo.xml
  • Unit tests: booking lifecycle, overlap prevention, billing linkage
  • UAT: walk-in vs online, reschedule flow, cancellation policy, feedback request, consumables

Performance Notes

  • Index commonly filtered fields: company_id, patient_id, doctor_id, room_id, state, start_datetime
  • Prefer domain filters in dashboards; avoid heavy computes in list views
  • Archive completed bookings periodically in high-volume environments

API Endpoints

  • controllers/website.py — website pages/forms (optional)

Upgrade & Migration

  • Normalized module prefix to clinic_*
  • Clean separation: Booking in clinic_booking, Appointment in clinic_doctor
  • Handshake policies (create/sync/cancel) configurable to avoid circular dependencies
