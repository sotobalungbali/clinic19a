ClinicOne — Branch & Location Management

Multi-Company • Multi-Branch • Multi-Site • Franchise-Ready

Pondasi manajemen cabang & lokasi untuk klinik kecantikan yang bertumbuh, dibangun di atas Odoo 18 Community Edition. Atur clinic.branch (unit bisnis) dan clinic.branch.location (site/ruang), kunci data & proses berdasarkan cabang, serta integrasikan ke Booking → Encounter/Procedure → Inventory → Billing → Reports.

Odoo 18 CE Multi-company Multi-site Portal-aware Audit Log Geo/Timezone

Overview

clinic_branch menghadirkan struktur enterprise untuk ekspansi cabang, franchise, atau multi-klinik. Setiap cabang memiliki identitas (alamat, timezone, logo), kebijakan (jam operasional, SOP), serta pengaturan default (gudang, jurnal, harga, header/footer dokumen). Akses, filter, dan pelaporan diikat ke cabang untuk kontrol dan akurasi operasional.

Key Features

  • Multi-Company & Multi-Branch dengan pembatasan akses dan visibilitas data.
  • Branch Locations (site/ruangan) untuk penjadwalan, resource, & room/equipment mapping.
  • Working Branch per user + Branch Switch Wizard untuk perpindahan cepat.
  • Default & Policies: warehouse, picking type, journals, sequences, pricelists, taxes.
  • Branding per cabang: logo, header/footer QWeb, alamat & kontak.
  • Geo: koordinat, timezone, region untuk SLA dan penjadwalan.
  • Record Rules ketat berbasis cabang/perusahaan + audit event utama.
  • Bridges ke Booking, Patient, Treatment, Billing, Inventory, Portal, Reports.
  • Merger tool (opsional): konsolidasi data saat akuisisi/penutupan cabang.

Core Models

  • clinic.branch — master cabang (identitas, kebijakan, default mapping).
  • clinic.branch.location — site/ruangan yang berelasi ke branch.
  • mixin.branch — field branch_id, company_id, dan guardrail _check_company.
  • res.company (inherit) — default branch & preferensi dokumen.
  • res.users (inherit) — working branch + allowed branches.
  • stock.warehouse / account.journal (inherit) — pemetaan per cabang.
  • QWeb — header/footer cetak menampilkan identitas cabang.

Semua model mengikuti konvensi Odoo 18 CE dan kompatibel multi-company.

Holistic Integrations (ClinicOne)

Terintegrasi mulus dengan: clinic_base, clinic_patient, clinic_doctor, clinic_booking, clinic_treatment, clinic_billing, clinic_ar, clinic_ap, clinic_finance, clinic_accounting, clinic_inventory, clinic_room_device, clinic_ecommerce, clinic_membership, clinic_feedback, clinic_reports, clinic_dashboard, clinic_wallet, clinic_package, clinic_portal, clinic_marketing, clinic_l10n_id, clinic_audit dan modul lain di proyek ClinicOne.

Integrasi soft-coupled melalui relasi opsional, hooks, dan bridges sehingga modul bisa dipasang dan ditingkatkan secara independen tanpa mematahkan alur lain.

Operations

  1. Setup Cabang: buat clinic.branch, tentukan warehouse, journals, sequences.
  2. Setup Lokasi: definisikan clinic.branch.location, room/equipment, jam operasional.
  3. Assign User: set allowed branches & working branch; gunakan wizard untuk switch.
  4. Transaksi: Booking/Encounter/Inventory/Billing otomatis terikat ke branch_id.
  5. Pelaporan: filter & agregasi berdasarkan cabang/perusahaan.

Security

  • Groups: Branch Manager, Branch User, Branch Readonly.
  • Record Rules: scope cabang + perusahaan; pembatasan edit lintas branch.
  • Audit: event perpindahan working branch, perubahan mapping default.

Defaults & Mapping

  • Warehouse, picking type, routes, & stock locations.
  • Account journals, sequences, taxes, analytic/ cost center.
  • Pricelists, payment methods, website store (opsional).

Installation

  1. Tambahkan addon ke addons_path Odoo.
  2. Update Apps list, cari ClinicOne — Branch & Location Management.
  3. Install; dependensi inti (base, mail, stock, account) akan terdeteksi.

Configuration

  • Buat clinic.branch dan tentukan mapping default (warehouse, journals, sequences, taxes).
  • Definisikan clinic.branch.location dan jam operasional.
  • Set allowed branches & working branch untuk setiap user.
  • Aktifkan bridges yang relevan (booking/patient/treatment/billing/inventory/portal/reports).

Demo & Testing

  • Demo data: contoh cabang, lokasi, mapping warehouse & journals.
  • Unit tests: record rules, working branch switch, konsistensi branch_id di transaksi.
  • UAT: Booking → Encounter → Billing → Report dengan multi-branch.

Performance Notes

  • Index pada branch_id, company_id, dan tanggal transaksi.
  • Gunakan read_group untuk laporan agregat lintas cabang.
  • Cron pembersihan log audit untuk menjaga ukuran database.

API & Bridges

  • models/bridges/bridge_booking.py — Booking & schedule per cabang.
  • bridge_patient.py — patient scope & statistik per cabang.
  • bridge_treatment.py — offering & katalog treatment per cabang.
  • bridge_billing.py — jurnal & sequence invoice per cabang.
  • bridge_inventory.py — warehouse & lokasi stok per cabang.
  • bridge_reports.py — filter & agregasi laporan per cabang.
  • controllers/portal.py — visibilitas data portal berdasarkan cabang (opsional).

Upgrade & Migration
