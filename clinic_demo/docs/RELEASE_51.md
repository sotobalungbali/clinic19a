1. Stop Odoo; replace the complete clinic_demo folder from this ZIP.
2. Start Odoo, Update Apps List, upgrade clinic_demo to 19.0.1.0.51.
3. Open the SAME Demo Run with Demo Safe Mode enabled; click Refresh Compatibility.

5. Expected target: READY FOR DEMO. Do not Reset Dataset, create a new run or manually edit fingerprints/groups.

## What is corrected

The source actor explicitly received Stock Manager but not Products/Create. Native Odoo 19 gives product.category, product.template and product.product create/write access through product.group_product_manager. Stock Manager alone is insufficient for creating the dedicated demo consumable and its category.

The functional DEMO-USER-MGR now receives product.group_product_manager as an explicit source-journey entitlement before ACL preflight. This covers category, variant and delegated product template. No System Administrator role, custom permissive ACL or sudo business creation is added.

All required group external IDs are resolved before any role assignment. Missing group definitions produce an aggregated error without partially assigning the other groups. Existing entitlements are retained; repeat preparation adds no duplicate links.

The existing full model/field/method/ACL preflight remains active. It now explicitly includes product.template read/create/write and the product.product.product_tmpl_id relationship, plus template UoM/category relations. This covers the delegated product path rather than only the four reported errors. Runtime constraints and record rules remain enforced on actual ORM writes.

The source action still preflights all five producers and Reports/Dashboard/Analytics before creating source business records. Deterministic names, anchor dates, reference ownership and drift checks remain intact. Stock and posted Wallet records are reused through their established contracts; metrics are generated by owner report engines, not fabricated. The historical Resources checkpoint repair is retained. Supported build adoption now includes v50 so no new fingerprint mismatch is required to install this repair.
