ClinicOne — Clinical Imaging Management

Requests • Studies • Structured Findings • Reporting • KPIs • Portal

End-to-end imaging workflow for Odoo 18 Community Edition: Request → Screening/Consent → Acquisition (Study/Series/Image) → Findings → Report/Sign-off → Billing → KPIs. Seamlessly integrates with the ClinicOne suite (patients, doctors/HR, booking, treatment, billing, portal, etc.).

Odoo 18 CE Multi-company Mail/Activities Dashboard/KPI Portal Sharing

Overview

The module introduces an imaging domain model (request, case header, study/series/image, findings, result/report, device registry), safety & consent flows, staff credentialing, and imaging-aware billing. All relations are soft-coupled so modules remain independently deployable while still providing deep cross-module context (appointment, encounter, treatment, prescription).

Key Features

  • Imaging Request lifecycle: Draft → Submitted/Approved → Scheduled → In Progress → Done/Cancelled.
  • Acquisition hierarchy: Study → Series → Image (binary, attachment, or external URL/UID).
  • Structured Findings & Reporting with sign policy (solo/co-sign/supervised) and digital signature.
  • Safety & Consent: contrast allergy, eGFR/renal risk, implants/MRI safety, sedation plan; consent templates & Q&A.
  • Device registry & staff competencies; authorized operators per modality/device.
  • Billing integration: imaging-aware invoices/lines, posting hooks, chatter tracebacks.
  • KPIs: throughput, TAT (request→acq, acq→sign, sign→invoice), revenue by modality/type, staff productivity.
  • Portal: key images & final results sharing with patient preferences.

Core Models

  • clinical.imaging.request — order entry (priority, indication, consent, preferred device)
  • clinical.imaging — case header bridging request→study/result (billing flags, context links)
  • clinical.imaging.study / .series / .image — acquisition timeline & operators; key images
  • clinical.imaging.finding — structured observations, severities
  • clinical.imaging.result — report authoring, sign-off/final/amend, portal flags
  • clinical.imaging.type — modality taxonomy; protocols
  • clinical.imaging.device — device registry, QA/QC attributes, authorized staff
  • account.move(_line) — imaging-aware billing fields & totals

Backward-compatible lookups and safe cross-module checks keep installs resilient when not all modules are present.

Installation

  1. Add this addon to your Odoo addons_path as clinic_imaging.
  2. Update Apps list, search ClinicOne: Clinical Imaging Management.
  3. Install; dependencies auto-resolve.

Configuration

  • Define Imaging Types (modality, contrast use, protocols).
  • Register Devices and assign authorized staff/competencies.
  • Configure Report Templates & signing policies.
  • Set up Consent Templates (contrast/MRI/sedation/radiation).

Security

  • Groups: Imaging User, Technologist, Radiologist, Imaging Manager.
  • Record Rules: company scope, portal sharing of key images/results.

Demo & Testing

  • Demo data: imaging types/devices, sample requests/studies/results (for sandbox only).
  • Unit tests: request workflow, acquisition chain, reporting/signing, billing hooks.
  • UAT scenarios: contrast/sedation flows, consent requirements, portal sharing, KPI snapshots.

Performance Notes

  • Index frequently filtered fields: patient_id, doctor_id, modality, imaging_type_id, state, request_datetime, study_datetime, signed_datetime.
  • Use domains in dashboards; avoid heavy computes in list/tree views.
  • Archive completed items periodically in high-volume environments.
