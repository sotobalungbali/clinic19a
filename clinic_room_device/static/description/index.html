ClinicOne — Clinical Room & Device Management

Room Catalog • Device Inventory • Assignment • Availability • Maintenance

Kelola ruangan klinik dan perangkat/alat medis secara terpadu: tipe & kapasitas ruang, kategori perangkat, penempatan (assignment), jadwal & ketersediaan (availability), serta request maintenance—terintegrasi dengan modul-modul ClinicOne lainnya. Kompatibel dengan Odoo 18 Community Edition.

Odoo 18 CE Multi-company Mail/Activities Maintenance Dashboards

Overview

Modul ini memusatkan pengelolaan master Ruang (tipe, kapasitas, fasilitas) dan Perangkat/Alat Medis (kategori, nomor seri, status kesiapan), termasuk riwayat penempatan, perpindahan antar-ruang, ketersediaan per shift, serta request maintenance. Dirancang untuk bekerja erat dengan Booking, Queue, Treatment, dan Inventory agar operasional klinik berjalan efisien.

Key Features

  • Master Room: tipe (Poli, Bed, Lab, Radiologi, dsb), kapasitas, status (Ready, In Use, Cleaning, Maintenance)
  • Master Device: kategori, nomor seri, umur pakai, status kesiapan (Available, Reserved, Offline, Maintenance)
  • Assignment perangkat ke ruangan dengan validasi konflik & histori perpindahan
  • Availability ruang & perangkat per shift (pagi/siang/malam) + template
  • Integrasi maintenance: request dari device/room, team, SLA hint, dan histori
  • Integrasi Queue & Booking: auto-suggest room/device sesuai treatment
  • Mail & Activities: notifikasi perubahan status/penempatan
  • Dashboard backend untuk overview okupansi & perangkat kritikal

Core Models

  • clinic.room — katalog ruangan, tipe, kapasitas, status, fasilitas
  • clinic.room.type — kamus tipe ruang
  • clinic.device — perangkat/alat medis, nomor seri, status kesiapan
  • clinic.device.category — kategori perangkat
  • clinic.room.device.assignment — penempatan perangkat ke ruangan (riwayat)
  • clinic.room.availability — slot/shift ketersediaan ruangan
  • clinic.device.movement — perpindahan perangkat, alasan, dan audit

Semua model dilengkapi mail.thread & mail.activity.mixin untuk jejak audit & kolaborasi.

Holistic Integrations (26 Modules)

Terintegrasi dengan: clinic_base, clinic_patient, clinic_hr, clinic_doctor, clinic_booking, clinic_queue_room, clinic_treatment, clinic_inventory, clinic_billing, clinic_ar, clinic_ap, clinic_finance, clinic_accounting, clinic_pricing, clinic_package, clinic_membership, clinic_wallet, clinic_ecommerce, clinic_portal, clinic_marketing, clinic_feedback, clinic_reports, clinic_dashboard, clinic_l10n_id, clinic_audit.

Integrasi dilakukan via relasi, server actions, activities, dan mail templates agar modul tetap loosely-coupled.

Installation

  1. Tambahkan addon ini ke addons_path Odoo Anda.
  2. Update daftar Apps, cari ClinicOne: Clinical Room & Device Management.
  3. Install; dependencies akan terpasang otomatis.

Configuration

  • Definisikan Room Types & Rooms dan set kapasitas serta status awal.
  • Tambahkan Device Categories & Devices (serial number, umur pakai, status).
  • Atur Availability Template (opsional) untuk shift ruang.
  • Konfigurasikan Maintenance Team & SLA hint bila digunakan.

Security

  • Groups: Room User, Device Technician, Room Supervisor, Admin.
  • Record Rules: pembatasan per company dan ruang/responsibility.

Wizards

  • wizard_device_assign — assign/unassign perangkat ke ruangan
  • wizard_room_device_move — pindah perangkat antar-ruang dengan validasi konflik
  • wizard_device_maintenance_request — buat request maintenance langsung dari device

Reports & Dashboards

  • Room Utilization & Occupancy
  • Device Readiness & Maintenance History
  • Critical Devices Watchlist

Assets

  • JS: room_board.js, device_overview.js
  • QWeb: room_board_templates.xml, device_overview_templates.xml
  • SCSS: room_board.scss, device_overview.scss

API Endpoints

  • controllers/room_api.py — JSON untuk status ruang & daftar okupansi
  • controllers/device_api.py — JSON untuk perangkat: readiness, assignment, movement
  • controllers/portal.py — status ketersediaan ruang untuk portal

Upgrade & Migration

  • Normalisasi prefix model menjadi clinic.* untuk konsistensi antar-modul.
  • Opsi pertahankan nama tabel lama via pengaturan _table pada model baru (jika migrasi).
  • Alias kelas dengan _register = False dapat disiapkan untuk kompatibilitas sementara.
